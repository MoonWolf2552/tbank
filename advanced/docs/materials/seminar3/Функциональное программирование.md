# Функциональное программирование и как оно сделано в Java

Краткая шпаргалка к семинару 3. Полноценная теория по лямбдам — в
[«Функциональные интерфейсы и лямбда-выражения»](./Функциональные%20интерфейсы%20и%20лямбда-выражения.md).

---

## Базовая теория: принципы ФП

1. **Чистые функции** — один и тот же вход всегда даёт один и тот же выход, нет побочных эффектов
   (не читает и не меняет внешнее состояние).
2. **Неизменяемость** — данные не изменяются, вместо этого создаются новые.
3. **Функции — значения первого класса** — можно передавать как аргумент, возвращать, хранить в переменной.
4. **Композиция** — сложное собирается из простых функций (выход одной → вход другой).
5. **Рекурсия вместо циклов** — циклы мутируют счётчик, что нарушает принципы 1–2.

Функциональный стиль — **декларативный**: описываем *что* нужно получить, а не *как* (через команды и мутацию
состояния). Ошибки, отсутствие значения, побочные эффекты становятся **значениями и типами**, видимыми в сигнатуре,
а не скрытым поведением.

## Как это сделано в Java

### Ключевая идея: в Java ФП — это имитация, а не природа языка

В Java нет «просто функций». Лямбда — это **синтаксический сахар над анонимным классом**, реализующим
**функциональный интерфейс** (интерфейс ровно с одним абстрактным методом). Без интерфейса «функция» не существует
в системе типов.

```java
// функциональный интерфейс — контракт с одним методом
interface Transformer {
    int apply(int x);
}

// лямбда = реализация интерфейса (сахар над анонимным классом)
Transformer double_ = x -> x * 2;
```

Сравнение с JS: в JS лямбда — самостоятельное значение (функция как функция). В Java лямбда обязана «влезть» в тип
функционального интерфейса — `Function`, `Predicate`, `Consumer`, `Supplier` из `java.util.function`.

### Основные функциональные интерфейсы

| Интерфейс | Сигнатура | Назначение |
|---|---|---|
| `Function<T,R>` | `R apply(T)` | преобразование |
| `Predicate<T>` | `boolean test(T)` | проверка условия |
| `Consumer<T>` | `void accept(T)` | потребление значения (побочный эффект) |
| `Supplier<T>` | `T get()` | поставка значения без аргументов |
| `UnaryOperator<T>` | `T apply(T)` | `Function`, где вход и выход одного типа |
| `BinaryOperator<T>` | `T apply(T, T)` | бинарная операция над двумя однотипными значениями |

### Чистота в Java

Проверка чистоты не встроена в язык — это дисциплина. Лямбда может захватывать внешние переменные, но только
**effectively final** (иначе не скомпилируется). Это ограничение и есть «жёсткая» часть — побочные эффекты через захват
переменных запрещены на уровне компилятора.

```java
int base = 10;                 // effectively final
Function<Integer, Integer> f = x -> x + base;   // ок
// base = 20;                 // нельзя: лямбда захватила бы «изменяющуюся» переменную
```

### Неизменяемость в Java

Не свойство языка, а соглашение + стандартные средства:
- `final` на ссылке **не** делает содержимое неизменяемым (`final List` ≠ иммутабельный список);
- `List.of(...)`, `Map.of(...)`, `Stream.toList()` — неизменяемые коллекции;
- переиспользование ссылки запрещено, содержимое — по договорённости.

### Функции как значения в Java

«Хранение», «передача», «возврат» функций в Java — на деле операции с **объектами функциональных интерфейсов**.

```java
// храним в переменной
Function<String, String> shout = s -> s + "!";

// передаём как аргумент
String twice(Function<String, String> fn, String v) {
    return fn.apply(fn.apply(v));
}

// возвращаем как значение (каррирование через вложенные лямбды)
Function<String, Function<String, String>> prefixer = pre -> str -> pre + str;
Function<String, String> greet = prefixer.apply("Hello, ");
greet.apply("world");            // "Hello, world"
```

### Метод-ссылки

Когда тело лямбды сводится к вызову одного существующего метода, его можно заменить ссылкой на метод:

```java
list.sort(Comparator.comparing(Instrument::getTicker));   // вместо i -> i.getTicker()
list.forEach(System.out::println);                        // вместо i -> System.out.println(i)
```

## Stream API — идиоматичный ФП в Java

Функциональные операции над коллекциями вынесены в отдельную библиотеку — `Stream`, а не в сами коллекции.
Цепочка: **источник → промежуточные операции (ленивые) → терминальная операция (запускает вычисление)**.

```java
int result = List.of("hello", "fp", "world")
        .stream()
        .filter(s -> s.length() > 3)      // промежуточная
        .map(String::toUpperCase)          // промежуточная
        .mapToInt(String::length)          // промежуточная
        .sum();                            // терминальная — только здесь всё выполняется
```

Типичные операции:

| Тип | Операции |
|---|---|
| Промежуточные | `filter`, `map`, `flatMap`, `distinct`, `sorted`, `limit`, `peek` |
| Терминальные | `collect`, `reduce`, `forEach`, `count`, `anyMatch`, `findFirst` |

Ленивость: промежуточные операции не выполняются, пока не вызвана терминальная. Это отличает Java-стримы от «жадных»
`map/filter` в JS-массивах.

## Ошибки и опциональность

- **Optional** — обёртка «значение есть / его нет», альтернатива `null`. Близка к монаде Maybe.
- **Vavr `Try` / `Either`** — ошибка как **значение**, а не пролетающее исключение (см. материал
  [«Vavr: Try и Either»](./Vavr%20Try%20и%20Either.md) и демо
  [`VavrDemo`](../../../src/main/java/academy/backend/market_pulse/demo/VavrDemo.java), где одна и та же операция
  показана на `try-catch` и на `Try`).

```java
// Java: исключение пробивается, ветвление в catch
// Vavr: ошибка стала значением, обработка — цепочкой методов
Try.of(() -> risky())
   .map(x -> x + 1)
   .recover(ex -> 0)
   .getOrElse(42);
```

## Сравнение: JS vs Java vs Haskell (шпаргалка)

| | JS | Java | Haskell |
|---|---|---|---|
| Функция как значение | да, по природе | через интерфейс (имитация) | да, по природе |
| Чистота | не гарантируется | дисциплина + effectively final | по умолчанию (через `IO`) |
| Неизменяемость | по договорённости | `final`/`List.of`/`toList()` | по построению |
| Коллекции | `map/filter/reduce` встроены | `Stream API` (отдельная библиотека) | `map/filter/fold` встроены |
| Ленивость | нет (eager) | да (стримы) | да, по умолчанию |
| Циклы | есть | есть + Stream | нет, только рекурсия |
