# Требования к файловому хранилищу

Самостоятельная работа к семинару 7 (см. «План семинара.md», раздел «Взаимодействие с файловой
системой» — вне тайминга занятия, на занятии или дома). Три независимых контракта, у каждого —
не только требования текстом, но и код для старта: интерфейс, заготовка с `TODO`, абстрактный тест
для самопроверки, эталонная реализация (не показывать студентам заранее, для разбора в начале
семинара 8 при необходимости).

## 1. Котировки отслеживаемых инструментов

- `repository/store/QuoteFileStore.java` — контракт.
- `repository/store/impl/QuoteFileStoreSkeleton.java` — заготовка, методы бросают
  `UnsupportedOperationException("TODO: ...")` с подсказками в комментариях.
- `repository/store/QuoteFileStoreContractTest.java` — абстрактный тест для самопроверки:
  скопировать файл, в `createStore()` вернуть свою реализацию.

```java
void save(Path path, List<Quote> quotes);
List<Quote> load(Path path);
```

Формат файла не навязывается. Обязательно:

1. `load(save(path, quotes))` возвращает те же котировки (тикер, тип, название, валюта, цена,
   изменение за период).
2. Если файла ещё нет — `load` возвращает пустой список, а не бросает исключение.

## 2. Watchlist

- `repository/store/WatchlistStore.java` — контракт.
- `repository/store/impl/WatchlistStoreSkeleton.java` — заготовка.
- `repository/store/WatchlistStoreContractTest.java` — абстрактный тест.

```java
void save(Path path, Set<String> tickers);
Set<String> load(Path path);
```

Обязательно:

1. `load(save(path, tickers))` возвращает тот же набор тикеров в том же порядке добавления.
2. Если файла ещё нет — `load` возвращает пустой набор, а не бросает исключение.

## 3. История цен

- `history/PriceHistoryStore.java` — контракт.
- `history/impl/PriceHistoryStoreSkeleton.java` — заготовка.
- `history/PriceHistoryStoreContractTest.java` — абстрактный тест.

```java
Path append(Path directory, PricePoint point);
List<PricePoint> load(Path directory, String ticker);
```

Отличие от двух предыдущих контрактов: это не «перезаписать файл целиком», а «дописать историю» —
каждый `append` создаёт **новый** файл, существующие не трогаются. Обязательно:

1. Каждый вызов `append` создаёт отдельный файл — предыдущие точки не теряются и не переписываются.
2. `load(directory, ticker)` возвращает все сохранённые по тикеру точки в порядке возрастания
   времени.
3. Если для тикера ещё нет точек — `load` возвращает пустой список, а не бросает исключение.

## Что уже готово вокруг контрактов (не часть самостоятельной работы)

- **Команда `update`** — через `TInvestApiClient` (см. этапы 2, 7 и 8) забирает актуальные котировки для
  тикеров из `Watchlist`, формирует новый файл через `QuoteFileStore` и пишет точку истории цены
  через `PriceHistoryStore` на каждый обновлённый инструмент.
- **Команда `watch`** — сохраняет watchlist через `WatchlistStore` сразу при добавлении тикера;
  `AppConfig` читает watchlist с диска при старте.
- **`FileBackedQuoteRepository`** — читает файл с котировками один раз и держит результат в памяти
  (кеш), не перечитывает на каждый запрос.
- **`QuoteFileWatcher`** (`WatchService`) — отслеживает изменение файла котировок на диске и
  инвалидирует кеш `FileBackedQuoteRepository`, чтобы следующее обращение перечитало актуальные
  данные.

`Main`/`AppConfig` используют эталонные реализации всех трёх контрактов — CLI работает уже сейчас;
заготовки (`*Skeleton`) существуют только для практики и никуда не подключены.

## Не требуется

- Поддержка конкурентного доступа к файлам из нескольких процессов.
- Миграция формата файла между версиями.
- Интеграция с `MappedByteBuffer` (см. [«MappedByteBuffer vs Files»](ByteBuffer/9.%20MappedByteBuffer%20vs%20Files.md)
  — для больших файлов, не для
  обычного размера файлов котировок/watchlist/истории).
