# Упражнения: Stream API

Самостоятельная практика (этап 4). 16 упражнений над одним и тем же списком из 10 котировок — от
простых фильтраций до Gatherer API. Формулировка каждого упражнения — javadoc метода в
`exercise/StreamExercises.java`; решение пишется в `exercise/StreamExercisesSkeleton.java`, метод за
методом.

---

## Как проверять себя

```bash
mvn -o -pl advanced test -Dtest=StreamExercisesSkeletonTest
```

Сразу после выдачи все 16 тестов красные (`throw new UnsupportedOperationException`) — это ожидаемо.
Реализовали упражнение — тест по нему зеленеет, остальные не трогаете. Полностью зелёный прогон —
все 16 упражнений решены.

---

## Список упражнений

| № | Упражнение | Что отрабатывает |
|---|---|---|
| 1 | Тикеры инструментов в заданной валюте | `filter` + `map` + `toList` |
| 2 | `N` самых дорогих котировок по убыванию цены | `sorted` + `limit` |
| 3 | Валюты, представленные в списке, без повторов | `map` + `distinct` |
| 4 | Есть ли хоть одна просевшая котировка | `anyMatch` (короткозамкнутая) |
| 5 | Сколько котировок заданного типа инструмента | `filter` + `count` |
| 6 | Суммарная цена всех котировок | `reduce` над `BigDecimal` |
| 7 | Средняя доходность по всем котировкам | `mapToDouble` + `average` |
| 8 | Количество котировок по типу инструмента | `groupingBy` + `counting` |
| 9 | Средняя доходность отдельно по каждому типу | `groupingBy` + `averagingDouble` |
| 10 | Разбить на выросшие и остальные | `partitioningBy` |
| 11 | Котировка по тикеру с разрешением дублей (цена выше — побеждает) | `toMap` с merge-функцией |
| 12 | Все тикеры одной строкой, через запятую, в скобках | `Collectors.joining(delimiter, prefix, suffix)` |
| 13 | Для каждой валюты — строка её тикеров через запятую | `groupingBy` + `mapping` + `joining` |
| 14 | Котировки по списку тикеров, неизвестные — пропустить | `map` в `Optional` + `flatMap(Optional::stream)` |
| 15 | Скользящее среднее цены по окну из `K` котировок | `Gatherers.windowSliding` |
| 16 | Длина самой длинной серии подряд идущих убыточных котировок | кастомный `Gatherer.ofSequential` с `finisher` |

Упражнения 1–5 — лёгкие (один проход, одна-две операции), 6–14 — средние (`reduce`, числовые стримы,
многоключевые коллекторы, `joining`), 15–16 — решаются через Gatherer API и требуют состояния между
соседними элементами конвейера, которое `map`/`filter`/`limit` выразить не могут.

---

## Подсказки по сложным упражнениям

> **Упражнение 11.** `Collectors.toMap(keyFn, valueFn, mergeFn)` — третий аргумент вызывается, только
> когда ключ уже встречался; возвращает тот из двух элементов, который должен остаться в `Map`.

> **Упражнение 13.** `mapping(downstreamMapper, downstreamCollector)` — адаптер-коллектор: сначала
> проецирует элемент группы (котировку в тикер), и только потом применяет к результату второй
> коллектор (`joining`). Без него `groupingBy` отдал бы вторым коллектором `joining` прямо на
> `Quote`, а `Quote` — не `CharSequence`, так не скомпилируется.

> **Упражнение 15.** `Gatherers.windowSliding(k)` сам собирает окна (`List<T>` на каждое окно) — после
> него остаётся обычный `map`, который считает среднее по одному окну.

> **Упражнение 16.** Состояние — счётчик текущей серии: растёт на убыточной котировке, на
> прибыльной/нулевой — испускается вниз по конвейеру (если он не нулевой) и сбрасывается. После
> последнего элемента в состоянии может остаться незавершённая серия — для этого у
> `Gatherer.ofSequential` есть третий, необязательный аргумент — `finisher`.
